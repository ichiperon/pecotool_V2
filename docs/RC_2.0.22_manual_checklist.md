## カテゴリ A — 最低保証ライン（保存の正しさ）

**出荷ゲート。A の不合格が1件でも存在する場合は NoGo。**

### A-1: 基本保存ラウンドトリップ
- [ ] 実PDF（5ページ以上）を開く → 全ページOCR → 上書き保存(Ctrl+S) → 完全終了・再起動 → 再オープンでOCRテキストが全ページ復元
- **期待**: 保存前後でOCRブロック（内容・位置）が全ページ一致 / ホワイトアウトなし / クラッシュなし
- **不合格**: 1ページでもOCRデータ消失 / ホワイトアウト / 保存中クラッシュ・フリーズ

### A-2: アトミック保存（中断保護）
- [ ] 大きめPDFをOCR → 通常保存 → 元ファイルが壊れていない（サイズ0や破損なし）
- **不合格**: 元ファイルがサイズ0 / 存在しない / 開けないPDFが生成される

### A-3: 別名保存（書き込み失敗フォールバック）
- [ ] 読み取り専用先へ上書き保存を試行 → 「別名で保存」案内 → 書込可能パスへ別名保存 → 作業内容が失われない
- **不合格**: エラーが無言で消える（作業消失）/ 案内なしクラッシュ

### A-4: ページ並べ替え後の保存整合性
- [ ] 並べ替え2回以上 → 保存 → 再起動・再オープンでページ順一致 / ページとOCRテキストの対応が正しい
- **不合格**: ページ順が戻る / 対応がずれる

### A-5: ページ回転後の保存整合性
- [ ] 90/180/270度回転 → 保存 → 再起動・再オープンで回転保持 / BBが回転後座標で正しい
- **不合格**: 回転リセット / BBが回転前位置に戻る

## カテゴリ C — PCT-049 回帰確認（御局指摘の必須シナリオ）

**壊れた1エントリを含む bbox-meta を実機で開いて保存まで通す。自動テストが緑でも実機IPCパスは別物。必ず実施。**

### C-1: 壊れた bbox-meta エントリを含むPDFの開封 — 隣接ページのOCRデータ生存
**背景**: PCT-049修正前は1件でも不正エントリがあると全ページのOCRデータが失われた（null返却）。修正後は不正エントリのみスキップし他ページを保護。
- [ ] 3ページ以上をOCR・保存 → `PecoToolBBoxes` メタを手動破壊（1ページ目に `"confidence": 9999` や `"x": "NaN"` 等を混入。または `savePathologicalAbnormal.test.ts` のフィクスチャ生成を参考に生成）→ 実機で開く → 1ページ目（不正）と2〜3ページ目（正常）のOCRパネル確認 → 上書き保存 → 再起動・再オープンで2〜3ページのOCRデータ生存
- **期待**: 不正ページは「OCRデータなし」/pdfjs fallback（許容） / **無関係ページのOCRテキストは生存（必須）** / 再オープンで隣接ページデータが消えない / クラッシュなし
- **不合格（NG-03）**: 壊れた1エントリで他ページのOCRデータが全消え / 開封時クラッシュ / 保存後再オープンで生存データ消失

### C-2: 全エントリ不正な bbox-meta のフォールバック
- [ ] 全エントリ不正（または空）の bbox-meta を持つPDFを実機で開く → OCRパネル・キャンバス確認
- **期待**: pdfjs fallback または「OCRデータなし」扱い / ホワイトアウトなし / クラッシュなし
- **不合格**: クラッシュ / ホワイトアウト

## カテゴリ D — PCT-046/047/048 回帰確認

### D-1: 単一ページOCR（PCT-046）
**背景**: 修正前は現在ページOCR時に `pageWidth` 未伝播でIPCエラー。修正後は `getPageSize` でサイズ取得。
- [ ] 中間ページに移動 → 「現在のページをOCR」→ テキスト表示 → 1ページ目でも同様に成功
- **不合格**: `run_ocr missing required key pageWidth` 相当のエラー / 完了せずタイムアウト

### D-2: 範囲指定OCR（PCT-046）
- [ ] 「範囲OCR」で矩形ドラッグ指定 → 完了 → 選択範囲内テキストが追加
- **不合格**: `width===0` / `pageWidth missing` 相当のエラー / 無応答

### D-3: 保存後の信頼度永続化と要確認マーク（PCT-047/048）
**背景**: 修正前は保存→再オープンで confidence が undefined 化しハイライト無効。PCT-048で要確認マークは空/重複ブロックのみ対象に変更。
- [ ] 全ページOCR → 「要確認マーク」ON → 空/重複ブロックに「空」「重なり」バッジ表示 → 該当ブロックにハイライト → トグルOFFで消える → ON+上書き保存 → 再起動・再オープン → ON で保存前と同じブロックにハイライト・バッジ
- **不合格**: 再オープンで要確認マークが全く出ない（PCT-047リグレ）/ OFFでハイライト残る / バッジが信頼度%表示（PCT-048リグレ）

## カテゴリ G — 2026-06-19 レビュー反映分（PCT-106〜117）

**今回リリースの新規確認項目。位置補正の全ページ適用経路に集中。自動テストでは届かない実機IPC・実キャンバス・外部ビューア目視を担う。**

### G-1: 位置補正既定0/0化と更新時マイグレーション（PCT-117）
**背景**: 位置補正の既定を 右4mm/下2mm → 0/0 に変更。ツール表示のBB枠と保存PDFのテキスト層を一致させるため。zustand persist の `version:1` + `migrate` で旧4/2永続値を 0/0 へリセット（他のOCR設定は保持）。
- [ ] **更新シナリオ**: 旧版（補正4mm/2mm設定が残っている環境）から v2.0.22 へ更新 → OCR設定を開く → 位置補正のオフセットが 0/0 になっている → 他のOCR設定（言語・要確認マーク等）は維持されている
- [ ] **BB一致目視（最重要）**: 0/0 のまま OCR → 上書き保存 → 保存PDFを **外部ビューア（Acrobat/Edge/ブラウザ等）** で開き、テキスト選択時の透明テキスト層がツール表示のBB位置と一致する
- [ ] **opt-in 補正**: 位置補正をONにして任意オフセット指定 → 保存 → 外部ビューアでオフセット分だけ意図通り移動。回転PDF（90/180/270）でも表示右下方向に一貫
- **期待**: 既定0/0でツールBBと保存テキスト層が一致 / 更新で旧4/2が0/0へリセット・他設定保持 / 補正ONは opt-in で意図通り
- **不合格（NG-07相当）**: 既定でBBと保存テキスト層が常時ずれる / 更新で他設定まで消える / 補正方向が回転で逆転

### G-2: 全ページ適用の per-page 失敗フォールバック（PCT-106）
**背景**: 修正前は `loadAllPagesWithTextBlocks` が1ページの抽出失敗で全体 reject → 保存丸ごと中断。修正後は per-page try-catch で失敗ページのみフォールバック（実 textBlocks を持つ existing のみ流用、無ければ元PDFのテキスト層を温存）。
- [ ] 一部ページの抽出が失敗しうるPDF（破損・特殊フォント等）で全ページ位置補正適用 → 保存 → 失敗ページは元PDFのテキスト層が温存され、他ページの保存は継続 → 失敗をトーストで可視化
- **期待**: 1ページの失敗で保存全体が中断しない / 失敗ページのテキスト層が空上書きで消えない / 失敗がユーザーに見える
- **不合格**: 1ページ失敗で保存丸ごと中断 / 失敗ページのテキストが空で上書きされ消失（NG-07相当）

### G-3: 回転・縦書きでの位置補正方向の一貫性（PCT-107）
**背景**: 回転(90/180/270)・縦書きの方向検証テストを新設し、全方向で表示右下へ一貫を確証済み（9件緑）。実機の外部ビューア目視で最終確認する。
- [ ] 縦書きPDF・各回転PDFで位置補正をONにして任意オフセット → 保存 → 外部ビューアでテキスト層のずれ方向が表示上の右下方向で一貫
- **不合格**: 特定の回転・縦書きでオフセット方向が逆転・直交方向にずれる

### G-4: 保存中の undo/redo によるページ対応のズレ防止（PCT-108）
**背景**: 修正前は保存の長い await 中に並べ替え undo/redo が走るとライブ pageOrder 遅延参照で IDBキーがズレ、編集が別ページに付く/欠落しうる。修正後は action 時点の pageOrder をキャプチャして渡す。
- [ ] 大きめPDF（保存に数秒かかる規模）を編集 → 上書き保存を開始 → **保存の進行中**に Ctrl+Z / Ctrl+Y で並べ替えを undo/redo → 保存完了後に再起動・再オープン → 各ページの編集内容が正しいページに対応している
- **不合格**: 編集が別ページに付く / ページ対応がずれる / 編集が欠落する（NG-07相当）

### G-5: 大規模全ページ適用の進捗とタイムアウト（PCT-109）
**背景**: 修正前は1000ページ規模で分オーダー＋固定600秒タイムアウトの崖＋進捗無表示でフリーズに見えた。修正後は進捗トースト（1秒間引き・最終ページ必出）＋動的タイムアウト `max(600_000, totalPages*1500)`。
- [ ] 数百〜可能なら1000ページ規模のPDFで全ページ位置補正適用 → 進捗トーストが表示され処理が進む → 完了する（タイムアウトの崖でフリーズしない）
- **不合格**: 進捗が一切出ずフリーズに見える / 大規模PDFでタイムアウト中断

## updater pubkey 設定の前提条件（SRE: 沙花叉）

**実機手動確認（上記 A/B/C/D/G）が通るまで pubkey の設定・コミット・出荷は行わない。**

- [ ] `tauri build` 実バイナリで保存機能を手動確認済み
- [ ] 表示の正しさ（ホワイトアウト無/BB位置）を手動確認済み
- [ ] OCR/IPC 変更の実機動作確認済み（自動緑のみでは不十分）
- [ ] 位置補正既定0/0と更新時マイグレーション（G-1）を実機確認済み
- [ ] 更新確認エンドポイントが稼働・正しいレスポンス形式
- [ ] 更新バイナリのホスティング先が確定・アクセス可能
- [ ] 段階ロールアウト or 配信停止スイッチが機能（エンドポイント実装依存）
- [ ] 秘密鍵を CI Secrets に登録済み（平文コミットなし）
- [ ] 秘密鍵バックアップ先確定・権限限定
- [ ] 漏洩時対処手順を関係者が把握
- [ ] 旧バージョンのインストーラを GitHub Releases 等に残置
- [ ] ユーザーへの緊急通知手段を確保
- [ ] Tauri v2 の signer コマンド名・環境変数名・updater スキーマを公式で確認

> 詳細手順・鍵管理・ロールバック設計は SRE 整理分を参照。既存 [docs/UPDATER.md](UPDATER.md) との突き合わせも実施すること。
> リリースノート記載事項（PCT-117 の既定リセット・PCT-115 の更新前保存推奨）は `docs/review_issues_2026-06-19.md` を参照。
